# 长沙国际会展中心 - 采购管理系统 使用说明

## 一、项目简介

这是一个基于 **React 18 + TypeScript + Vite** 开发的企业级采购管理系统，面向会展行业的物资采购、供应商管理、合同管理全流程业务。

### 功能模块一览

系统分为 **采购管理** 和 **仓库管理** 两大业务域，共约 25 个子模块：

---

## 二、合约管理核心设计（对齐 Excel 文档）

### 2.1 招采类合同 vs 非招采类合同

| 维度 | 招采类合同 | 非招采类合同 |
|------|-----------|-------------|
| 来源 | 招采流程自动带入 | 经办人手动填写 |
| 合同名称 | 自动带入前期招采 | 手动填写 |
| 合同形成方式 | 法定招标/自愿招标/国企采购-询比/竞价/谈判/直接/框架/电子商城（8种） | 展览服务/展览展示服务/招商合同/其他（4种） |
| 合同类型 | 工程类/非工程类 | 工程类-施工/服务/货物、非工程类-服务/货物（5种） |
| 中标时间 | ✅ 有 | ❌ 无 |
| 履约评价（保证金/质保金） | ✅ 开关，自动关联合同履约评估 | ❌ 无 |
| 考核管理（月度/季度/单个项目） | ✅ 下拉，自动关联供应商考核 | ❌ 无 |
| 年度评价 | ✅ 开关，自动关联供应商年度评价 | ❌ 无 |
| 履约保证金 | ❌ 无 | ✅ **门控逻辑**：只有合同形成方式=展览服务时才显示 |

### 2.2 合同台账（26 列，按 Excel 顺序）

```
合同性质 | 合同名称 | 合同编号 | 合同类型 | 合同形成方式 | 中标时间 | 示范文本
→ 经办部门 | 经办人 | 联系方式 | 对方单位 | 对方负责人
→ 签订日期 | 生效日期 | 终止日期
→ 合同金额 | 采购申请金额 | 采购申请比(自动算) | 已支付金额 | 结算金额
→ 合同履行情况 | 资金流向 | 归档情况 | 状态 | 备注 | 操作
```

### 2.3 合同预警提醒（紧凑设计）

- **原来**：内嵌 ~200 行大面板，压屏严重
- **现在**：顶部紧凑条（🔔 N 条预警 · 📊 统计汇总按钮），点击弹出 Modal 看详情
- **支持的预警类型**：
  - 支付预警（已支付占比 ≥ 阈值，默认 80%）
  - 到期预警（终止日期前 N 天，默认 30 天）
  - 考核提醒（绑定的合同考核到期前 N 天，默认 7 天）
- **提醒设置**：可配置阈值和提前天数

## 七、核心数据模型

### 7.1 合同台账 ContractLedger

```typescript
{
  // 顶层区分（必填）
  contractNature: 'procurement' | 'non_procurement',

  // 根据 contractNature 动态取值
  formation: ProcurementFormation | NonProcurementFormation,
  contractType: ProcurementContractType | NonProcurementContractType,

  // Excel 列头要求的字段
  winningDate?: string,           // 中标时间（招采类有效）
  isModelText?: boolean,          // 示范文本（是/否）
  handlerContact?: string,        // 我方单位-联系方式
  requisitionAmount?: number,     // 采购申请金额（预留）
  archiveStatus?: 'not_started' | 'in_progress' | 'archived',
  // ... 更多字段见 types/index.ts
}
```

## 八、常见问题

### Q1：npm install 报错？
```bash
npm cache clean --force
npm config set registry https://registry.npmmirror.com
```

### Q2：端口被占用？
默认 5174 端口，修改 `vite.config.ts` 的 `port` 或关闭占用程序。

### Q3：数据从哪来？
演示数据全部内置在 `src/mock/data.ts`，存储使用 Zustand + localStorage 持久化（刷新页面数据不丢）。

### Q4：是纯前端演示吗？
**是**。所有数据保存在浏览器 localStorage，更换浏览器/清除缓存就重置。没有后端服务调用。
