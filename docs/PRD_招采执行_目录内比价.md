# PRD：招采执行 — 框架协议采购·目录内比价

> 录入系统：禅道（开发任务单）
> 涉及页面：CompetitiveBiddingPage（招采执行）→ SupplierQuoteSimulator（供应商端小程序）→ SupplierQuotePage（报价管理）

---

## 一、需求背景

招采需求确认通过后，进入"实质性采购执行"环节。9 种采购方式中，**框架协议采购·目录内比价**是唯一走"线上报价 → 采购方采纳定标 → 回写工单 → 自动生成采购订单"链路的方式。

**核心差异**：供应商不直接给采购工单写报价，而是**报价单存在独立的报价管理池里**。采购方必须**在报价管理页拍板选谁、回写工单**，然后招采执行工单才能继续走评审→完成→生成订单。不采纳不回写，整条链断住。

其余 8 种采购方式（询比/竞价/谈判/直接/电子商城/随机抽取/法定招标/自愿招标）不走线上报价，采购方在工单手填中标结果后直接走验收兜底。本 PRD 只描述目录内比价这一条链路。

## 二、需求详细描述

### 2.1 采购方侧（招采执行页 CompetitiveBiddingPage）—— 新建工单 + 状态机

#### 2.1.1 新建工单

采购方点击「新增招采执行」，弹窗中：
1. **选择采购方式**：默认"框架协议采购·目录内比价"
2. **关联采购需求**：弹窗选需求 → 自动把需求明细带入工单 items（编码、名称、规格、单位、数量、需求单价、审计单价）
3. **每条物资补充必填**：
   - 含税上限单价（保存校验 > 0）
   - 单价说明下拉：只有两个选项——**「固定单价」或「上限单价」**
     选"上限单价"时供应商端小程序会显示灰色小字预算上限提示
   - 不含税单价列（保存时系统自动 × 数量 = 供应商不含税金额）
4. **整单含税上限总价**（保存校验 > 0）
5. **比价结果汇总·不含税总金额**（保存时必须 = 清单不含税金额合计，容差 0.01 元）
6. **受邀供应商**（多选，弹窗选）
7. **竞价公告 / 竞价文件**：页面头部统一上传（已删除逐行上传列，所有条目共享）
8. **保存**：自动生成工单编号 `JJ+年月日+3位序号`

#### 2.1.2 状态机按钮链（操作列按状态依次出现）

| 当前状态 | 可点按钮 | 动作 | 校验 |
|---------|---------|------|------|
| **draft** | 发布 | 状态→已发布 | 清单非空，每条上限单价都 > 0 |
| **published** | 开始采购 | 状态→招标中，给受邀供应商发通知 | 无 |
| | 设置招标时间 / 修改招标时间 | 弹窗选开始/截止 | 开始 < 截止；截止后冻结 |
| **bidding** | 评审 | 状态→已评审 | 无 |
| | 修改招标时间 | 同上 | 截止前可改 |
| **evaluated** | 完成 | 状态→已完成；自动取最低合格报价为中标 | 必须至少有 1 个合格报价（**前提：报价管理页已采纳并回写，Bidding.quotes 有数据**）|
| | 上传评定结果 | 弹窗上传 | 状态 ∈ {已评审, 已完成}，最多 3 个附件 |
| **completed** | 生成采购订单 | 一键生成 CPO 订单 | 可重复生成（弹窗确认）|

**关键前提**：状态机推进到"完成"之前，**报价管理页必须已做了"采纳 + 回写"**。如果没有回写，Bidding.quotes 为空，"完成"按钮点不了。

### 2.2 供应商侧（小程序 SupplierQuoteSimulator）—— 提交报价单

#### 2.2.1 受邀工单列表

供应商登录 → 看到"受邀的目录内比价工单"列表（来自采购方在工单里选的受邀供应商）。

每张卡片显示：工单编号、项目名称、招标时间（红色=已截止）、招标状态。

#### 2.2.2 填写报价

进入工单详情页：

**清单明细表**（从工单 items 带入，只读展示工单配置的上限）：

| 列 | 类型 | 说明 |
|----|------|------|
| 序号 | 只读 | |
| 项目概况·物料名称 | 只读 | |
| 合同费率 | 只读 | 元/月，合同内物资才有 |
| 不含税单价（采购方填的基线） | 只读 | 灰色背景 |
| 数量 / 单位 | 只读 | |
| **报价单价（供应商填）** | 输入框 | 数字，实时校验 |
| 单价说明 | 只读 | 显示采购方选的"固定单价"还是"上限单价" |

**单价说明联动提示**：
- 采购方选了「上限单价」→ 报价输入框下方显示灰色小字：`↑ 预算上限 ¥XXX/份，建议报价不得超过此价`
- 报价超上限 → 整行红色边框 + 数字红色 + 红色警告条：`⚠ 超预算上限，报价将判不合格`

**底部合计区**：自动算含税总额 + 不含税总额 + 税额合计，实时更新。

#### 2.2.3 提交报价单

所有必填行都填了报价单价 → 提交 → 二次确认 → 成功。

**⚠️ 报价单写入 SupplierQuote store**（独立的报价管理池），**不直接写入 Bidding.quotes**。要送到采购工单，必须走报价管理页的"回写工单"。

### 2.3 采购方侧（报价管理页 SupplierQuotePage）—— 拍板定标

**这是整条链路的关键环节。不在这里采纳并回写，招采执行工单就拿不到中标结果，后面全走不下去。**

#### 2.3.1 三种视图模式

| 视图 | 适用场景 | 聚合维度 |
|------|---------|---------|
| **按报价单** | 一家供应商一张单，整张单整体比价 | `(报价单 id)` |
| **按物资（推荐）** | 同一工单不同物资可以选不同供应商（最灵活）| `(工单 + 物资)` |
| **按工单汇总** | 看一张工单下所有供应商整体情况 | `(工单)` |

#### 2.3.2 操作清单（核心业务逻辑）

**报价单有 3 种状态**：已提交 submitted → 已采纳 accepted / 已驳回 rejected

| 操作 | 状态限制 | 逻辑 | 后果 |
|------|---------|------|------|
| **采纳**（按报价单视图） | 仅已提交 | 找**同一工单下所有已提交报价**，取含税总额最低的一张：唯一→直接采纳；并列→弹窗人工指定一家 | 被选中的→已采纳；**其余自动变已驳回**（落标留痕）|
| **采纳**（按物资视图） | 该物资有已提交报价 | 找**同一工单 + 同一物资下所有已提交报价**，取该物资单价最低的一张；并列弹窗人工指定 | 被选中的报价单→已采纳。同一工单**其他物资**的报价不受影响（可以同一工单不同物资选不同供应商）|
| **回写工单** | 仅已采纳 | 把已采纳报价映射成 BiddingQuote → 写入对应工单的 `Bidding.quotes` 数组 | **结果送回招采执行工单**，工单才能继续走评审→完成→生成订单。重复回写会被拦截 |
| **驳回** | 仅已提交 | 按报价单视图：驳回当前这一张。按物资视图：驳回该工单该物资下**所有未采纳的已提交报价**（批量）| 状态变已驳回（不可恢复为已采纳，正式报价不要走删除）|
| **查看详情** | 任何状态 | 弹窗看整张报价单明细 | 纯查看 |
| **删除** | 任何状态 | 物理删除报价单 | **不可恢复且不留痕**。仅用于清理演示/错误数据，正式报价应走"驳回" |

#### 2.3.3 并列最低价的人工选择弹窗

无论按报价单还是按物资视图，最低价出现并列（≥2 家同价）时，弹出选择弹窗：
- 列出所有同价候选供应商（名称 + 报价单编号 + 报价总额）
- 采购方点选一家
- 确认后：选中的→已采纳；其余同价的→已驳回，并在 remark 里写"最低价相同未选中"

#### 2.3.4 回写工单的数据映射

handleSyncToBidding 函数做的事：

```
SupplierQuote（报价管理池）  ──映射──▶  BiddingQuote（工单.quotes 数组）
  supplierId / supplierName              supplierId / supplierName
  details[] 逐行映射                      details[]（逐行算 isOverSingleLimit）
  totalAmount                            totalAmount
  taxAmount                              taxAmount
                                         isQualified = !isOverSingle && !isOverTotal
                                         isOverSingleLimit / isOverTotalLimit
                                         confirmedSupplierId / Name（标记这是回写定标）
```

回写后工单状态自动推进：如果工单还在 draft 或 published，自动 → bidding。

### 2.4 评审与完成（回到招采执行页 CompetitiveBiddingPage）

**前提**：报价管理页已做了"采纳 + 回写"，Bidding.quotes 里有了数据。

#### 评审（状态→已评审）
- 点击「评审」按钮
- 状态变为 evaluated
- 可以上传评定结果附件（最多 3 个，可选）

#### 完成（状态→已完成）
- 点击「完成」按钮
- 系统从 Bidding.quotes 里筛选 **isQualified === true** 的报价单
- 取 totalAmount（含税总额）最低的一家 → 写入工单 winningSupplierId / winningSupplierName
- 状态变为 completed
- **如果没有任何合格报价** → 弹窗提示"没有符合条件的供应商报价"，阻止完成

#### 生成采购订单
- 已完成状态点击「生成采购订单」
- 订单明细取工单 items，含税上限价作为订单单价
- 订单写入 ProcurementOrder store，进入采购订单管理页
- 仓库凭此订单收货入库

## 三、业务规则与边界条件

| # | 规则 | 说明 |
|---|------|------|
| 1 | 工单编号自动生成 | 保存时 `JJ+年月日+3位序号`，锁定不可编辑 |
| 2 | 清单保存校验 | 每条上限单价 > 0 + 比价结果汇总 = 清单合计（容差 0.01）|
| 3 | 招标截止冻结 | 供应商不能再报价；采购方不能改截止时间 |
| 4 | 采纳后自动驳回其余 | 按报价单视图：同工单其余已提交 → 自动已驳回；按物资视图：同物资其余已提交 → 自动已驳回 |
| 5 | 不回写=链断 | 报价管理页采纳后必须回写，否则招采执行页 quotes 空，"完成"按钮点不了 |
| 6 | 超上限自动判不合格 | 报价单价超单品上限 / 总额超整单上限 → isQualified=false，不参与中标候选 |
| 7 | 并列最低价人工选 | 采纳时出现同价 → 弹窗人工指定一家 |
| 8 | 单价说明固定 2 选 1 | 只有「固定单价」和「上限单价」 |
| 9 | 竞价文件头部统一上传 | 所有清单条目共享，已删除逐行上传列 |
| 10 | 评定结果附件最多 3 个 | 已评审/已完成状态可上传 |
| 11 | 8 种方式不走订单 | 只有目录内比价生成订单，其余验收页从需求明细兜底 |
| 12 | 生成订单可重复 | 每次新增一条，弹窗确认 |
| 13 | 回写工单幂等 | 同一报价重复回写 → 拦截提示 |

## 四、数据对象流转（三张 store 的写入顺序）

```
SupplierQuote store              Bidding store                    ProcurementOrder store
（独立报价池）                   （招采执行工单）                  （采购订单）
─────────────────               ──────────────                  ──────────────

供应商报价 → SupplierQuote                     采纳+回写 → BiddingQuote 数组
（status=submitted）           ←───────────────────────────
                               quotes[] 有数据了
                               ↑
                               │ 评审 → 完成
                               │ 系统从 quotes 取最低合格
                               │ → winningSupplierId / Name

                               状态 → completed
                                          │
                                          ▼ 生成采购订单
                               Bidding.items 映射 → ProcurementOrder.details[]
                               winningSupplier → 订单.supplier
                               orderNo = CPO + 年月日 + 3位序号
```
