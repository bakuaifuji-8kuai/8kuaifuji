招采需求明细多合同关联
& 明细级聚合预警

让合同精确关联到需求明细行，多条合同可全额关联同一明细，预警取 MAX 对比预算；招采执行清单展开多供应商报价；帮助手册 + 变更记录同步更新。

1 需求原文 + 业务场景

需求原文（两版）

Round 1：招采模块，一个项目中的招采需求中的需求明细项需要 100 个，单价 500 元，可能需要几个供应商一起来做。但是每个供应商签的合同都是 100×500=50000 元。合同预警又需要按照项目中该条需求明细总金额 50000 元来预警。
Round 2（补充）：招采执行页面中，清单列表中也要展示同一条需求明细，对应多个中标供应商及其报价。

完整业务链路

CatalogCompareItem
🆕 展开多供应商报价
↕
合同 × N
每个合同都是全额
detailLinks ← detailId

2 核心数据模型改动 · 3 处（v2 新增 2 处）

① ContractLedger（合同侧，v1 已有）

// ContractLedger · 加 1 个可选字段 detailLinks?: Array<interface { demandId: string; demandNo?: string; detailId: string; // 精确到需求明细行 }>;

② CatalogCompareItem（招采执行明细，🆕 v2 新增）

// CatalogCompareItem · 加精确外键 + 多中标供应商 demandId?: string; 🆕 关联的需求单 ID demandDetailId?: string; 🆕 关联的需求明细行 ID // 原来只有 1 个中标供应商字段 → 扩成数组 // winningSupplierName?: string; // ⚠️ 旧字段保留兼容 winningSuppliers?: Array<interface { 🆕 多中标供应商 supplierId: string; supplierName: string; unitPrice: number; // 该供应商的中标单价 quoteId?: string; // 关联 BiddingQuote.id confirmedAt?: string; }>;

③ OfflineDetailItem（线下录入明细，🆕 v2 新增）

// OfflineDetailItem · 加精确外键（线下流程也能勾到需求明细） demandId?: string; 🆕 demandDetailId?: string; 🆕 winningSuppliers?: Array<...>; 🆕 同 CatalogCompareItem
💡
为什么加外键而不是靠 productCode 匹配？ 理论上 CatalogCompareItem.productCode 和需求明细 productCode 能对上，但多个需求单里可能出现相同 productCode 的不同物资。
显式 demandId + demandDetailId 外键是精确匹配，不会串单。
外键在招采执行工单从需求单导入明细时自动写入，用户不用手动填。
🔄
persist 迁移计划：version 21 → version 22
· ContractLedger 补 detailLinks = []（可选，老数据无风险）
· CatalogCompareItem / OfflineDetailItem 补 demandId / demandDetailId = undefined（可选）
· winningSupplierName 旧字段保留，winningSuppliers 数组如果存在则保留，不存在自动从单个字段包装成 [{ supplierId: '', supplierName: oldName }]

❌ 不做什么

  • 不自动按明细预算填合同金额——合同金额用户自己填
  • 不做分摊金额字段——取 MAX 不取 SUM
  • 不限制一条明细能被几个合同关联
  • 不改 linkedDemandIds 粗粒度关联——继续保留，detailLinks 是精确补充
  • 合同删除不事件同步回写——靠 useMemo 自动重算
  • 随机抽取（framework_random）不强制 detailLinks——降级
  • 非招采合同默认不显示 detailLinks
  • 不做需求侧任何类型定义——聚合纯计算
  • 不引入第三方 UI 库
